# Автоперевод манги: как реализовать дёшево

Дата: 2026-10-23

## 1. Что уже есть у других

| Проект | Где работает | Детекция | OCR | Перевод | Рендер |
|---|---|---|---|---|---|
| manga-image-translator | ПК/сервер (Python, GPU, Docker ~15 ГБ) | свои детекторы (ctd, dbconvnext…) | 48px, manga-ocr | DeepL, Gemini, ChatGPT, офлайн NLLB/M2M100/Sugoi/Qwen2 | LaMa-инпейнтинг + вёрстка текста |
| manga-translator-android (jedzqer) | Android, на устройстве | YOLO-seg TFLite (пузыри + текст вне пузырей) | PP-OCR ONNX (JA/EN/ZH), отдельная модель для KO | OpenAI-совместимый API + глоссарий на папку | плашки поверх оригинала, без инпейнтинга |
| overlay-translator | Android, перевод экрана | — | ML Kit / PaddleOCR / manga-ocr | офлайн или self-hosted | оверлей |
| Mangra, Manga Web Translator | iOS | на устройстве | Apple Vision | Apple Translate (бесплатно, офлайн) | оверлей |

**Среди читалок (Mihon, Kotatsu, Komikku) встроенного автоперевода нет.** Это реальная ниша.

## 2. Пайплайн

```
страница ─► [1] детекция ─► [2] OCR ─► [3] сборка текста ─► [4] перевод ─► [5] рендер ─► кэш
             пузыри/        по каждому   порядок чтения,     батч на        заливка
             текст          региону      склейка строк       главу +        пузыря +
                                                             глоссарий      вписывание
                                                                            текста
```

1. **Детекция.** Модель сегментации пузырей (маска нужна для заливки) + детектор строк текста. На устройстве: TFLite/ONNX, примерно 10–40 МБ.
2. **OCR.** Зависит от языка оригинала:
   - EN/KO/ZH: **ML Kit Text Recognition v2**: бесплатно, на устройстве, поддерживает латиницу, китайский, японский и корейский.
   - JA (вертикальный текст): **manga-ocr** (ONNX ~140 МБ, есть готовый экспорт) или PP-OCR, дообученный на манге. ML Kit с вертикальным японским справляется плохо — проверить на тестах.
3. **Сборка.** Порядок пузырей (RTL для манги, LTR для манхвы/комиксов), склейка строк внутри пузыря, отсев мусора (SFX, номера страниц).
4. **Перевод.** Заменяемые движки, см. §3. Главная экономия: **один запрос на страницу или главу**, а не на каждый пузырь. Пузыри нумеруются, ответ приходит в JSON. Контекст главы и глоссарий имён резко повышают качество.
5. **Рендер.** Заливаем маску пузыря цветом фона (медиана по краю) и вписываем текст с автоподбором размера шрифта и переносами. Текст вне пузырей кладём на полупрозрачную плашку. LaMa-инпейнтинг (~200 МБ) — опция на потом.
6. **Кэш.** Room: `(хэш_изображения, язык, движок, версия_промпта) → регионы + перевод`. Перевод выполняется один раз, повторное чтение бесплатно.

## 3. Движки перевода по стоимости

| Уровень | Движок | Цена для нас | Качество | Замечания |
|---|---|---|---|---|
| **0. Офлайн** | ML Kit Translation | 0 | низкое–среднее | 50+ языков, пакет на язык. Перевод идёт через английский: JA→RU = JA→EN→RU. Нужна атрибуция |
| 0. Офлайн | Своя модель (opus-mt / NLLB-distilled через ONNX Runtime) | 0 | среднее | +100–600 МБ на языковую пару, медленно на слабых устройствах |
| **1. Ключ пользователя (BYOK)** | **Gemini API** (Flash/Flash-Lite, бесплатный тариф) | 0 | **высокое** | Порядка 1000–1500 запросов/день на Flash-Lite (лимиты меняются, проверять в AI Studio). Батч главы = 1 запрос. Режим «отправить картинку» — OCR и перевод одним шагом |
| 1. BYOK | DeepL API Free | 0 | хорошее | 500 тыс. символов/мес |
| 1. BYOK | Любой OpenAI-совместимый (OpenRouter, DeepSeek, Groq, локальный Ollama/LM Studio по Wi-Fi) | 0 / копейки | высокое | Один клиент покрывает десятки провайдеров |
| ⚠️ | Неофициальный эндпоинт Google Translate | 0 | среднее | Нарушает ToS, может сломаться в любой момент. Не закладывать в основу |

**Объём:** глава ≈ 20 стр. × ~10 пузырей × ~15–30 символов ≈ 3–6 тыс. символов.
DeepL Free → ~100 глав/мес, Gemini → практически без ограничений для одного человека.

Gemini Nano (ML Kit Prompt API) отклонён: работает только на ограниченном списке флагманов, протестировать нельзя.

### Решение: пользователь выбирает движок

| Движок | Тип | Что нужно от пользователя | Фича-флаг по умолчанию |
|---|---|---|---|
| ML Kit Translation | офлайн | скачать языковой пакет | **по умолчанию без ключа** |
| Офлайн-модель (opus-mt / NLLB-distilled, ONNX Runtime) | офлайн | скачать модель пары (100–600 МБ) | опция |
| Gemini API | облако, BYOK | API-ключ из AI Studio | **рекомендуемый** |
| OpenAI-совместимый | облако/локально, BYOK | base URL + ключ + имя модели | опция |
| DeepL API Free | облако, BYOK | API-ключ | опция |

Неофициальный эндпоинт Google Translate в список **не входит** (ToS, нестабильность).

- Выбор глобально в настройках + переопределение на уровне тайтла.
- Цепочка fallback: если выбранный облачный движок недоступен (нет сети, лимит, ошибка ключа) — автоматически ML Kit, с уведомлением.
- LLM-движки (Gemini, OpenAI-совместимый) получают батч главы + глоссарий; классические (DeepL, ML Kit, офлайн-модель) — батч пузырей страницы без глоссария-промпта (глоссарий применяется постобработкой/через glossary API DeepL).
- Счётчик использования для движков с месячными лимитами (DeepL).

**Принцип: у приложения нет своего бэкенда и своих платных ключей.** Пользователь вставляет свой бесплатный ключ (Gemini получается за минуту в AI Studio), а без ключа всё работает офлайн. Наши затраты — 0, юридическая поверхность минимальная.

## 4. Режимы

- **«Быстрый» (офлайн):** детекция + OCR на устройстве, ML Kit или офлайн-модель.
- **«Качественный» (рекомендуемый):** детекция + OCR на устройстве, текст всей главы одним запросом в LLM (Gemini/OpenAI-совместимый) с глоссарием → дёшево по токенам, контекстно, перевод согласован между страницами.
- **«Vision»:** страница целиком уходит в мультимодальную модель, она возвращает регионы и перевод. Проще всего в реализации, но координаты менее точные и токенов больше. Fallback для сложных страниц.

## 5. UX

- Переключатель «оригинал ↔ перевод» в ридере (тап двумя пальцами / кнопка), долгий тап по пузырю — оригинал + правка.
- **Предперевод:** при открытии главы фоново переводим следующие N страниц (корутины), «перевести главу/тайтл заранее» — через WorkManager вместе с загрузкой.
- Настройки на уровне тайтла: язык оригинала, направление чтения, движок, глоссарий (имена копятся автоматически: LLM возвращает новые имена в ответе).
- Экспорт переведённой главы в CBZ.

## 6. Место в архитектуре

```
:feature:translation
  ├─ TextDetector        (BubbleSegDetector — TFLite/ONNX)
  ├─ OcrEngine           (MlKitOcr, MangaOcrOnnx, PaddleOcrOnnx)
  ├─ Translator          (MlKitTranslator, OnnxMtTranslator, GeminiApiTranslator,
  │                       OpenAiCompatTranslator, DeepLTranslator)
  ├─ TranslatorRegistry  (выбор движка: глобально / на тайтл, fallback-цепочка)
  ├─ PageTranslator      (оркестратор пайплайна, батчинг, ретраи, лимиты)
  ├─ TranslationCache    (Room)
  ├─ Glossary            (на тайтл)
  └─ OverlayRenderer     (Canvas/Compose поверх SubsamplingImageView, или запекание в Bitmap)
```
Модели (OCR/детекция/языковые пакеты) скачиваются по требованию, а не лежат в APK.

## 7. Риски

- **Лицензии моделей:** YOLO от Ultralytics — AGPL-3.0, это повлияет на лицензию приложения. Альтернативы: PP-OCR (Apache-2.0), RT-DETR, своя дообученная модель. Проверить лицензию каждой модели до встраивания.
- **Вертикальный японский** — самое слабое место on-device OCR, нужен тестовый набор страниц.
- **Лимиты бесплатных API** меняются: выносим в настройки, показываем счётчик, при исчерпании переходим на офлайн-движок.
- **Производительность:** детекция + OCR ≈ 0.3–1.5 с/стр. на среднем телефоне (оценка, проверить). Поэтому предперевод и кэш обязательны.

## 8. План внедрения

1. Прототип на 20–30 тестовых страницах (JA/KO/EN): сравнить ML Kit OCR, manga-ocr и PP-OCR по качеству и скорости.
2. MVP: детекция + OCR + экран выбора движка + Gemini BYOK (батч главы) + ML Kit офлайн + оверлей + кэш.
3. Затем: OpenAI-совместимый клиент, DeepL, глоссарий, предперевод, офлайн-модель ONNX.
4. Потом: инпейнтинг, Vision-режим, экспорт CBZ.

## 9. Что реализовано в M4 (первая версия)

- **Распознавание:** ML Kit Text Recognition v2, модели латиницы, японского, корейского и китайского встроены в APK. Язык оригинала берётся из метаданных тайтла (ComicInfo, MangaDex, Komga); если он неизвестен — японская модель (она читает и латиницу). Отдельный детектор пузырей и manga-ocr пока не подключены.
- **Перевод:** ML Kit (офлайн, по умолчанию) и Gemini (`generateContent`, свой ключ, страница одним запросом, ответ в JSON со схемой). Модель по умолчанию `gemini-3.5-flash-lite`, меняется в настройках. Ключ хранится зашифрованным (Android Keystore).
- **Откат:** если Gemini недоступен (нет ключа, неверный ключ, лимит, нет сети), страница переводится через ML Kit, а ридер показывает причину.
- **Отрисовка:** перевод рисуется на копии страницы (белая плашка + текст с подбором размера), ридер показывает её вместо оригинала — зум и вебтун работают без пересчёта координат. Если перевод совпал с оригиналом (имена, номера), оригинал не закрывается.
- **Кэш:** Room, таблица `translation_page`, ключ — источник + глава + номер страницы, язык и движок с версией промпта.
- **Ридер:** кнопка перевода в меню, автоперевод при открытии (настройка), заранее переводятся 2 следующие страницы.

**Не сделано в M4:** OpenAI-совместимый движок, DeepL, офлайн-модель ONNX, глоссарий имён, перевод главы одним запросом, инпейнтинг вместо плашек, детектор пузырей для вертикального японского. Gemini проверен тестами на MockWebServer, вживую — только с ключом пользователя.
