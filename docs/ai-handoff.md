## Часть 1. Проект и правила

### Что это
Tsunayomi — Android-читалка манги (Kotlin, Jetpack Compose) с автопереводом страниц. Репозиторий:
`github.com/Kingofthedivanich/Tsunayomi`, ветка `main`, лицензия GPL-3.0. Интерфейс на русском и английском.
Последний релиз — `v0.9.0`.

Стек: Kotlin 2.4, AGP 9.4, Gradle 9.8 (convention-плагины в `build-logic`, version catalog
`gradle/libs.versions.toml`), Compose + Material3, Hilt, Room (сейчас БД v6, AutoMigration), DataStore,
OkHttp 5, Coil 3, WorkManager, ML Kit (OCR и офлайн-перевод), ONNX Runtime 1.28 (manga-ocr).

### Карта модулей (то, что понадобится)
| Модуль | Что там |

| `source/{mangadex,komga,local,webtoons,naver,remanga,asura}` | Встроенные источники |
| `extension/lib` | API расширений Tachiyomi/Mihon (код Mihon, Apache-2.0): `HttpSource`, `NetworkHelper`, `CloudflareInterceptor`, `WebViewInterceptor`, `AndroidCookieJar`, `WebViewUtil` |
| `extension/manager` | Загрузка APK-расширений, `ExtensionManager`, адаптер `ExtensionCatalogSource`, `ExtensionImageInterceptor` (картинки через клиент расширения по адресам `https://extension.tsunayomi.invalid/...`) |
| `feature/extensions` | Экран расширений, репозиториев и настроек источника |
| `feature/browse` | Список источников, каталог (`CatalogScreen`/`CatalogViewModel`), глобальный поиск |
| `feature/details` | Карточка тайтла |
| `feature/reader` | Читалка, `ReaderViewModel` (окна перевода, переключатель перевода) |
| `translation/api` | `TextRecognizer`, `Translator`, `JapaneseOcrProvider`, модели |
| `translation/core` | `DefaultPageTranslator`: распознавание → группировка пузырей → (manga-ocr для японского) → перевод → кэш |
| `translation/{mlkit,gemini,openai,deepl,mangaocr}` | Движки |
| `core/network` | Общий `OkHttpClient`, `@SharedInterceptor` (перехватчики, которые источники добавляют в общий клиент) |

| `feature/settings` | Настройки, онбординг, конфигурация API (`ApiConfigContent`, `ApiConfigViewModel`) |

### Сборка и проверки
```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
./gradlew assembleDebug lintDebug test testDebugUnitTest
```
- Перед каждым коммитом всё это должно проходить. Lint настроен с `abortOnError`.
- `MissingTranslation` — ошибка: каждая строка нужна и в `values/strings.xml`, и в `values-ru/strings.xml`.
- Результаты сборки лежат в `build.nosync/` и `.gradle.nosync/`: папка проекта синхронизируется с iCloud,
  и обычный `build/` ломает слияние ресурсов.
- APK: `app/build.nosync/outputs/apk/debug/app-arm64-v8a-debug.apk`. Сборка разбита по ABI.

### Устройства
- Эмулятор, AVD `tsunayomi_test` (arm64, Android 16). Запуск:
  `/opt/homebrew/share/android-commandlinetools/emulator/emulator -avd tsunayomi_test -no-window -no-audio -no-snapshot-save &`
- Телефон пользователя, серийный номер `35071FDH20000S`. Ставить только с `--user 0`:
  `adb -s 35071FDH20000S install --user 0 -r app/build.nosync/outputs/apk/debug/app-arm64-v8a-debug.apk`.
  Без него приложение попадёт и в рабочий профиль.
- Пакет debug-сборки — `app.tsunayomi.debug`, release — `app.tsunayomi`.

### Обязательные правила
1. **Коммиты** — на русском, автор берётся из `git config` репозитория (noreply-адрес пользователя).
   **Никаких** `Co-Authored-By`, «Generated with…» и прочих упоминаний ИИ в коммитах и PR.
   Теги и релизы пушить только после явного «да» пользователя.
2. **Секреты.** Пароли, ключи API и ключ подписи пользователь вводит сам. Не проси их в чате и не печатай.
   `tsunayomi-release.jks` и `keystore.properties` никогда не коммитятся.
3. **Приватность.** Приложение никуда ничего не отправляет, кроме запросов к источникам и к API перевода,
   которые настроил пользователь. Каждую новую библиотеку проверяй на телеметрию. Пример: ONNX Runtime
   с 1.29 сам шлёт статистику через ContentProvider — поэтому стоит 1.28, а provider вырезан в
   `translation/mangaocr/src/main/AndroidManifest.xml`.
4. **Release и R8.** Библиотеки, которые ходят в Java через JNI или рефлексию, ломаются от R8 только в
   release. Так было с ML Kit, ONNX Runtime и API расширений: нужны keep-правила в `consumer-rules.pro`.
   Любую задачу, которая добавляет такие библиотеки, проверяй на release-сборке:
   ```bash
   ./gradlew assembleRelease
   BT=$(ls -d /opt/homebrew/share/android-commandlinetools/build-tools/* | tail -1)
   $BT/zipalign -f 4 app/build.nosync/outputs/apk/release/app-arm64-v8a-release-unsigned.apk /tmp/rel.apk
   PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH $BT/apksigner sign --ks ~/.android/debug.keystore \
     --ks-pass pass:android --key-pass pass:android --ks-key-alias androiddebugkey /tmp/rel.apk
   adb -s emulator-5554 install -r /tmp/rel.apk
   ```
5. **«Работает» — только после проверки вживую.** Юнит-тесты на выдуманном HTML/JSON не доказывают, что
   источник работает. Предыдущий исполнитель сдал Naver, Remanga и manga-ocr с зелёными тестами, а они не
   работали: сайт стал JS-приложением, у API поменялась схема, OCR был заглушкой. Для сетевого кода сделай
   временный тест по живому сайту, прогони его и удали перед коммитом. Потом проверь на эмуляторе всю
   цепочку: каталог → тайтл → главы → страницы в читалке.
6. **Контракт источников** (`source/api`):
   - `getChapters()` возвращает главы **в порядке чтения**, первая глава первой. От этого зависят
     «следующая глава» и обновления.
   - `SManga.originalLang` — язык **текста на страницах**, а не оригинала произведения. Английский скан
     корейской манхвы — `"en"`. По этому полю выбирается OCR.
   - Тело ответа читай вне главного потока (`withContext(Dispatchers.IO)`): `await()` асинхронный, а чтение
     body — нет.
   - Перехватчики в `@SharedInterceptor` действуют на **все** запросы приложения. Ограничивай их точными
     хостами и не перезаписывай заголовки широко. Перехватчик Webtoons ставил свой Referer всем
     `*.pstatic.net` и ломал картинки Naver.
   - `id` источника — `sourceIdOf(name, lang)`, совместимо с Tachiyomi. Если расширение совпадает по id со
     встроенным источником, побеждает встроенный (`SourceManager.sorted`).
7. **Стиль.** Пиши как окружающий код: KDoc и комментарии объясняют «почему», а не «что».
   Пользовательские тексты — только через строковые ресурсы. Хардкод русских строк в data-слое и в
   источниках не допускается.

## Часть 2. Что сделано после правок Antigravity

Antigravity добавил 13 коммитов (`9a3c2cc`…`aea76fd`). Их проверили и исправили тремя коммитами.

### `0f78a34` — исправления после проверки
- **Naver Webtoon** переписан на JSON API сайта:
  - `comic.naver.com/api/webtoon/titlelist/weekday`, `/api/search/all`, `/api/article/list/info`,
    `/api/article/list`; картинки — из `#sectionContWide img` страницы просмотра, с Referer
    `https://comic.naver.com/`;
  - платные эпизоды (`charge`) и 18+ пропускаются;
  - раньше источник парсил HTML, которого больше нет, и читал ответ в главном потоке.
- **WebtoonsInterceptor** теперь трогает только `webtoon-phinf`, `swebtoon-phinf` и
  `webtoons-static.pstatic.net`.
- **Webtoons и Asura** отдают `originalLang = "en"`, раньше было `"ko"`, и OCR искал корейский.
- **Remanga и Asura** отдают главы в порядке чтения.
- **Remanga:** `type` в ответе API стал объектом `{id, name}`, а DTO ждал строку, и все главы падали при
  разборе. Теперь поле — `JsonElement`.
- **Категории:** недостающие стандартные («Читаю», «Прочитано», «Буду читать», «Брошено») создаются и
  тогда, когда у пользователя уже есть свои; уведомления о новых главах приходят только для «Читаю».
  Флаг перенесён на ключ `default_categories_initialized_v2`, чтобы исправление один раз сработало и у
  тех, у кого старая версия заполнение пропустила. Заполнение идёт под `Mutex`.
- **CBR:** RAR5 и архивы с паролем дают понятную `UnsupportedArchiveException`. JUnrar читает только RAR4.
- **Бэкап:** восстановление идёт одной транзакцией (`DatabaseTransactions` в `core/database`) и
  `channelFlow`.
- **Проверка ключей API:** `ApiCheckException(reason)` с переводом в UI; ключ Gemini передаётся в
  заголовке `x-goog-api-key`; тело запроса к OpenAI собирается через `buildJsonObject`.
- **App Lock на Android 8–10:** `BIOMETRIC_WEAK | DEVICE_CREDENTIAL`, раньше блокировка там не включалась.
- **Фильтры Asura** — на английском.

### `95a80eb` — рабочий manga-ocr
- Новый модуль `translation/mangaocr`:
  - модель `l0wgear/manga-ocr-2025-onnx`, закреплённая на коммите `e8b27bbd…` (Apache-2.0, ~134 МБ:
    ViT-энкодер + двухслойный BERT-декодер без KV-кэша);
  - скачивается по кнопке (`MangaOcrModelManager`);
  - `MangaOcrRecognizer`: жадное декодирование, до 96 токенов; пре- и постобработка как в оригинальном
    manga-ocr (`MangaOcrText`).
- `DefaultPageTranslator` перечитывает manga-ocr'ом **сгруппированные** пузыри с каной или кандзи. ML Kit
  только находит пузыри: вертикальный текст он режет на столбцы и путает их порядок. Переводы с manga-ocr
  кэшируются отдельно (тег `mocr1` в ключе).
- Карточка модели вернулась в настройки API, шаг — в онбординг.
- ONNX Runtime 1.28.0 из-за телеметрии в 1.29+; keep-правило `-keep class ai.onnxruntime.** { *; }`.
- Проверено на эмуляторе в debug и release на японском ваншоте с MangaDex.

### `6148e6c` — manga-ocr только для японского
При `sourceLang == null` (автоопределение) страница перечитывается, только если хотя бы в одном пузыре есть
кана: иероглифы без каны могут быть китайским текстом.

### Что известно и не исправлено
- APK для arm64 вырос примерно до 68 МБ: `libonnxruntime.so` занимает около 29 МБ.
- Популярное на Remanga почти целиком из платных тайтлов: в приложении у них «0 глав».
- Вживую не проверены бэкап и восстановление, открытие CBR/EPUB с устройства, биометрия.

1. В `MangaEntity` добавить nullable-колонку `translate_pages` (`Boolean?`, `null` = «не выбирал»).
   - БД → версия 7 через `AutoMigration(from = 6, to = 7)`.
   - Схема `7.json` генерируется в `core/database/schemas/` — закоммитить её.
2. Прокинуть поле в модель `Manga`, маппер и `MangaRepository` (метод `setTranslatePages(mangaId, Boolean)`).
3. `ReaderViewModel`:
   - при открытии `translationOn = manga.translatePages ?: settings.translateByDefault`;
   - `toggleTranslation()` сохраняет значение в тайтл.
4. В бэкап (`core/model/Backup.kt`, `BackupRepository`) добавить поле с значением по умолчанию `null`,
   чтобы старые бэкапы читались.
5. Тесты:
   - миграция 6→7 (`MigrationTestHelper`, если тестов миграций нет — хотя бы проверка схемы);
   - ViewModel/репозиторий: значение сохраняется, восстанавливается, у нового тайтла берётся из настройки.

**Готово, когда:** на эмуляторе включил перевод → закрыл главу → открыл следующую главу того же тайтла, и
перевод включён; у другого тайтла — по настройке.

### Задача 2. Экран WebView для ручной проверки Cloudflare

**Сейчас.** `extension/lib/.../CloudflareInterceptor.kt` решает только автоматические проверки в скрытом
WebView. Если нужна капча, пользователь видит ошибку «Не удалось пройти проверку Cloudflare…»
(`extension_lib_cloudflare_bypass_failure`).

**Сделать.**
1. В `source/api` у `CatalogSource` — методы с реализацией по умолчанию:
   `fun webUrl(): String? = null` и `fun webUrl(manga: SManga): String? = null`.
   - Реализовать во встроенных источниках, где это осмысленно.
   - В `ExtensionCatalogSource` — через `HttpSource.baseUrl` / `getMangaUrl()`.
2. Экран `WebViewScreen(url, sourceId)`, например в `feature/browse` или новом `feature/webview`:
   - `AndroidView { WebView }`;
   - настройки как `setDefaultSettings()` из `eu.kanade.tachiyomi.util.system.WebViewUtil`;
   - User-Agent как у `NetworkHelper.defaultUserAgentProvider()`;
   - cookies общие через `CookieManager`: `AndroidCookieJar` уже читает из него;
   - в тулбаре — заголовок страницы, «обновить», «открыть в браузере», «закрыть».
3. Куда встроить:
   - в `CatalogScreen` и карточке тайтла — пункт меню «Открыть в WebView», если `webUrl` не `null`;
   - на экране ошибки — кнопка «Открыть в WebView», если ошибка от Cloudflare. Сделай для этого отдельный
     тип исключения, например `CloudflareChallengeException : IOException`, в `extension/lib` вместо голого
     `IOException`, и распознавай его по типу, а не по тексту;
   - после возврата с экрана — автоматический `reload()`.
4. Строки — в `values` и `values-ru`.

**Готово, когда:** на эмуляторе расширение сайта с ручной проверкой Cloudflare после прохождения проверки
в WebView открывает каталог. Приложи скриншот или опиши, на каком расширении проверил.

### Задача 4. Проверенные парсеры из kotatsu-parsers

**Контекст.** `KotatsuApp/kotatsu-parsers` в архиве с ноября 2025: Kotatsu закрылся из-за претензий Kakao.
Живые форки: `Gekkoushi/plugin-source` (GPL-3.0, обновлялся в сентябре 2026, около 1,3 тысячи источников)
и `Shebyyy/kotatsu-multi-parsers` (обновлялся в октябре 2026). Пользователь хочет **только проверенно
рабочие** парсеры.

**Сделать.**
1. Выбрать форк: какой собирается, какой свежее, совместима ли лицензия (нужна GPL-3.0). Подключить как
   зависимость (JitPack, закреплённый коммит) или как git-сабмодуль с исходниками — выбор обосновать.
2. Модуль `source/kotatsu`:
   - реализация `MangaLoaderContext`:
     - HTTP — общий `OkHttpClient` и отдельный клиент с cookie jar на `CookieManager`;
     - выполнение JS — через QuickJS: он уже есть благодаря `extension/lib`;
     - настройки парсера — `SharedPreferences` на источник;
   - адаптер парсер → `CatalogSource`, по образцу `extension/manager/ExtensionCatalogSource.kt`:
     фильтры, порядок глав (первая первой), `originalLang` = язык страниц, картинки с нужными заголовками;
   - источники — через `DynamicSources` или `@IntoSet` (решить, где лучше).
3. **Автопроверка** — `source/kotatsu/src/test/.../ParserHealthTest`, запускается вручную, а не в CI:
   - для каждого парсера по живому сайту: популярное не пустое → детали → главы не пустые → страницы не
     пустые → первая картинка скачивается с HTTP 200 и `Content-Type: image/*`;
   - таймауты и параллельность, чтобы прогон шёл десятки минут, а не часы;
   - результат — файл `source/kotatsu/src/main/assets/allowlist.json` (имя парсера, язык, дата
     проверки) плюс отчёт по упавшим с причинами.
4. В приложении показывать только парсеры из allowlist. Исключить:
   - дубли встроенных источников и расширений — по домену;
   - сайты с контентом Kakao (KakaoPage/Piccoma и их зеркала);
   - 18+ скрыть тем же переключателем, что в `feature/extensions` (`ExtensionManager.showNsfw`).
5. В «Обзоре» — фильтр по языкам, как у расширений (`ExtensionManager.languages`).
6. В `docs/release.md` — пункт «перед релизом перегенерировать allowlist».
7. Release-проверка: парсеры часто используют рефлексию и сериализацию — проверить, что R8 их не ломает.

**Готово, когда:**
- в «Обзоре» есть N парсеров из allowlist;
- на эмуляторе вживую проверено не меньше 5 из них на разных языках (en, ru, ja/ko) по всей цепочке до
  читалки, включая release-сборку;
- отчёт: сколько парсеров проверено, сколько прошло, основные причины отказов.

### Задача 5. Сравнить Opus-MT и NLLB-200 с ML Kit
Сначала **исследование на компьютере**, встраивание — только если качество заметно лучше.

1. **Набор для оценки** — около 200 реплик из настоящей манги: японский, корейский, китайский поровну.
   - Брать текст, который выдаёт наш же OCR (ML Kit, а для японского manga-ocr), а не идеальный — так
     проверяется то, что реально придёт в переводчик.
   - Набор и скрипты — в `tools/mt-eval/`. Изображения не коммитить: только тексты и ссылки на главы.
2. **Эталон** — переводы Gemini (ключ даёт пользователь, сам не проси — пусть запустит скрипт).
   Пометь, что это «серебряный», а не ручной эталон.
3. **Кандидаты**, направления в английский и в русский:
   - ML Kit — от него сравниваем. Пары ML Kit для неанглийских языков, по всей видимости, идут через
     английский;
   - Opus-MT (Helsinki-NLP): `opus-mt-ja-en`, `opus-mt-ko-en`, `opus-mt-zh-en`; в русский — прямые пары,
     если есть, иначе через английский;
   - NLLB-200 distilled 600M: прямые пары в обе стороны.
4. **Метрики:**
   - chrF++ относительно эталона;
   - слепое сравнение с перемешанным порядком систем на выборке в 50 строк;
   - 20 строк на оценку пользователю: сделай для этого простую страницу или таблицу.
5. **Замеры на устройстве** — на эмуляторе arm64 и, если пользователь согласен, на его телефоне: размер
   модели, время на страницу из 10–15 пузырей, пик памяти. Модели — в ONNX с квантованием int8.
6. **Порог «заметно лучше»:**
   - выигрыш у ML Kit в слепом сравнении не меньше чем в 2 случаях из 3;
   - перевод страницы не дольше примерно 3 секунд на телефоне среднего уровня.

   Не проходит — пиши отчёт, и задача закрыта.
7. **Если проходит** — встроить:
   - новый `TranslationEngine` и модуль `translation/offline` на ONNX Runtime (он уже подключён);
   - токенизатор SentencePiece на Kotlin — проверь лицензии готовых реализаций;
   - скачивание модели по запросу, как `MangaOcrModelManager`;
   - в настройках и онбординге — предложение скачать с размером и сравнением качества;
   - при скачанной модели использовать её вместо ML Kit и как офлайн-движок, и как запасной, когда Gemini
     недоступен (`DefaultPageTranslator`, ветка fallback);
   - у NLLB лицензия CC-BY-NC — явно написать об этом в настройках и README.

**Готово, когда:** есть отчёт `tools/mt-eval/REPORT.md` с цифрами и решением. Если модель встроена —
перевод на ней проверен на эмуляторе в debug и release.

## Часть 4. Обязательная проверка перед сдачей

Задача сделана, только когда ты сам увидел результат в приложении на эмуляторе и можешь это показать.
«Тесты зелёные» и «должно работать» — не доказательство.

### 4.1. Инструменты
У тебя есть эмулятор и `adb`. Управлять приложением можно без человека:
```bash
# запуск debug-сборки
adb -s emulator-5554 install -r app/build.nosync/outputs/apk/debug/app-arm64-v8a-debug.apk
adb -s emulator-5554 shell am start -n app.tsunayomi.debug/app.tsunayomi.MainActivity
# что сейчас на экране: тексты, описания и координаты элементов
adb -s emulator-5554 shell uiautomator dump /sdcard/ui.xml && adb -s emulator-5554 shell cat /sdcard/ui.xml
# нажатие по центру нужного элемента (координаты — из bounds в дампе), ввод текста, «назад»
adb -s emulator-5554 shell input tap X Y
adb -s emulator-5554 shell input text "query"      # пробел — %s
adb -s emulator-5554 shell input keyevent 4
# скриншот — открой его и посмотри сам, текстовый дамп не показывает картинки
adb -s emulator-5554 exec-out screencap -p > shot.png
# падения и ошибки
adb -s emulator-5554 logcat -d -b crash
adb -s emulator-5554 logcat -d | grep -iE "exception|error" | tail -50
# чистое состояние (онбординг, пустая база)
adb -s emulator-5554 shell pm clear app.tsunayomi.debug
```
Удобно написать маленький скрипт: найти элемент по тексту в дампе и нажать на него. Учти, что
`input text` иногда искажает ввод в полях Compose — проверяй, что попало в поле.

### 4.2. Сетевой код — проверка по живому сайту
Для любого источника, парсера, API перевода или загрузки модели:
1. Временный JVM-тест (`src/test/.../LiveProbeTest.kt`), который на реальном сервере проходит всю цепочку
   и печатает результат: популярное → детали → главы (количество, порядок номеров) → страницы
   (количество, первый URL). Для API — реальный ответ, разобранный твоими DTO.
2. Прогон: `./gradlew :module:testDebugUnitTest --tests '*LiveProbeTest*' -i | grep PROBE`.
3. Любое исключение разбора — это баг в DTO, а не «сайт временно недоступен». Разберись по сырому ответу
   через `curl`.
4. Перед коммитом тест удали. Юнит-тесты на фикстурах оставь, но сами фикстуры снимай с **настоящих**
   ответов, а не придумывай.
5. Картинки проверяй отдельно (`curl -I` с теми же заголовками): многие CDN отдают 403 без нужного Referer.

### 4.3. Проверка задачи в приложении
По критерию «Готово, когда» своей задачи — на эмуляторе, через UI, со скриншотами ключевых экранов.
Обязательно:
- путь пользователя целиком, а не только экран, который менял: открыть → действие → результат →
  закрыть → открыть снова (состояние сохранилось?);
- ошибочный путь: нет сети (`adb shell svc wifi disable; svc data disable`), неверный ключ, пустой
  результат — приложение не падает, сообщение понятное и переведено;
- поворот экрана или сворачивание посреди операции, если задача про долгие операции;
- русский и английский интерфейс (язык приложения — в настройках Android для приложения) — нет ли
  непереведённых строк.

### 4.4. Регрессионный прогон (после каждой задачи, которая трогает общий код)
Сломать соседнее легко: так было с перехватчиком Webtoons и картинками Naver. После изменений в
`source/api`, `data`, `core/*`, `translation/core`, перехватчиках или навигации пройди всё по списку:

| Что | Как проверить |
|---|---|
| Встроенные источники | Webtoons, Naver Webtoon, Remanga (тайтл из «Новое»), Asura Scans, MangaDex: каталог с обложками → тайтл → главы → глава открывается, страницы видны. «Следующая глава» ведёт к бо́льшему номеру. «Язык страниц» в карточке верный: en / ko / ru / en / по главе. |
| Расширения | Репозиторий `https://raw.githubusercontent.com/keiyoushi/extensions/repo/index.min.json` добавляется; Weeb Central ставится; каталог → глава → страницы; шестерёнка настроек у Asura Scans (расширение) открывается. |
| Перевод | В читалке «Переводить страницы» → на английской главе через ML Kit (без ключа) появляются переводы на пузырях; следующие страницы переводятся по мере листания. |
| manga-ocr | Скачивание модели в «Конфигурация API» доходит до «Модель готова»; японская глава на MangaDex (фильтр Japanese, тайтл «Gold Gold Adventure Gold») переводится осмысленно; на корейской и английской главах модель не вызывается. |
| Библиотека и обновления | Добавить тайтл в «Читаю» → свайп вниз в «Библиотеке» запускает проверку → вкладка «Обновления» открывается. Бейдж «прочитано / всего» верный. |
| Загрузки | Скачать главу → открыть без сети → страницы есть. |
| Бэкап | «Создать копию» → `pm clear` → онбординг → «Восстановить» → библиотека, категории, прогресс и история на месте. Файл можно положить на эмулятор через `adb push` в `Download/`. |
| Локальные файлы | В `Download/` эмулятора папка с CBZ, EPUB и CBR (RAR4) — всё открывается; RAR5 — понятное сообщение. |
| Безопасность | Инкогнито → глава не попадает в «Историю». |
| Падения | `logcat -b crash` пуст за весь прогон. |

### 4.5. Release-сборка
Обязательна, если задача добавила зависимость, сериализацию, рефлексию или JNI, и перед выпуском — всегда.
Команды — в части 1, правило 4. На release-сборке повтори проверку задачи и строки таблицы 4.4, которые
она затрагивает. Пакет release — `app.tsunayomi`: это отдельное приложение с отдельными данными.

### 4.6. Самопроверка кода перед коммитом
```bash
git diff --stat
git diff | grep -nE "^\+.*(TODO|FIXME|NotImplemented|isAvailable\(\): Boolean = false|return emptyList\(\)|catch \(.*Throwable\) \{\s*\}|println\()"
grep -rn '"[^"]*[А-Яа-я][^"]*"' --include=*.kt <изменённые модули>/src/main   # хардкод русских строк
```
- Каждую находку исправь или объясни в отчёте.
- Нет ли заглушек: методов, которые всегда возвращают «недоступно», пустой список или `null`?
- Нет ли проглоченных ошибок: `catch` без логирования и без сообщения пользователю?
- `CancellationException` не должна глотаться в `catch (e: Exception)`.
- Новые зависимости: проверена ли телеметрия, нужны ли keep-правила, какой прирост размера APK?

### 4.7. Отчёт пользователю — в таком виде
1. **Сделано** — по пунктам, со ссылками на коммиты.
2. **Проверено вживую** — что именно и где (debug, release, эмулятор), со скриншотами ключевых экранов.
3. **Live-проба** — вывод `PROBE` для сетевого кода.
4. **Регрессия** — какие строки таблицы 4.4 прошёл.
5. **Не проверено и почему** — честно. «Не смог проверить X, потому что Y» лучше, чем молчание.
6. **Известные ограничения** — что работает не во всех случаях.

Если какой-то пункт проверки не прошёл, задача не сдана: чини и проверяй заново.
